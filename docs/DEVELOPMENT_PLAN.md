# 分阶段开发与验收

## 执行约定

阶段按依赖交付；任务ID与进度见TASKS.md。所有业务接口必须真实连接PostgreSQL，前端不得自行决定奖励。每个阶段完成定义包含迁移、错误状态、权限、验证和对应文档。后续变更先更新PRD及契约，再实现。

| 阶段 | 依赖 | 主要模块/数据库 | API和前端交付 | 验收 |
|---|---|---|---|---|
| P0 契约 | 无 | docs、OpenAPI、状态机 | 页面结构与接口输入输出 | 七份文档一致、无业务决策空缺 |
| P1 基础认证 | P0 | core、db、auth；用户/会话/成员/活跃日 | 登录、CSRF、多账号与管理布局 | 双标签页、单账号退出、权限隔离 |
| P2 任务 | P1 | tasks；任务/版本/每日实例 | 三种规则、准备查询、完成/取消、任务表单与今日页 | 历史不变、未来预览、日期边界与幂等 |
| P3 内容 | P1 | cards；分类/集/卡/媒体 | 内容CRUD、上传与后台、12张示例卡 | 上传安全、归档保护、重启持久化 |
| P4 奖励 | P2/P3 | rewards；奖励/会话/候选/获得/收藏 | 解锁、恢复候选、提交选择、补领 | 并发唯一、固定候选、故障回滚 |
| P5 图鉴 | P4 | 复用收藏与获得事实 | 筛选、详情、进度、重复数量 | 数量与进度口径一致、下架仍可查看 |
| P6 回顾管理 | P2/P4/P5 | admin与查询索引 | 月历、账号维护、记录、7/30天指标 | 数字可核对、补领日期正确、后台隔离 |
| P7 发布 | P6 | infra、scripts、PWA、测试 | 响应式、离线提示、Compose与TLS、备份恢复 | 构建/测试、空目标恢复、部署说明 |

## 测试层次

1. 规则单元测试：单次、每日、星期组合、开始结束边界。
2. 真实PostgreSQL集成：迁移、约束、快照、权限、历史保护。
3. 并发与故障注入：完成最后任务、生成候选、不同卡同时选择、收藏写入失败。
4. Playwright：真实前后端登录到图鉴、多账号/双标签页/延迟响应/退出、后台创建账号与上传。
5. 运维：独立schema迁移、生产构建、Nginx配置、数据库与图片恢复、恢复后幂等重试。

测试仅使用随机schema或独立测试数据库，禁止清空业务库。迁移需能从空库升级，后续版本需能从上一修订升级。

## 发布与回滚

本地先使用开发入口5173联调；Compose独立部署默认8080，生产叠加TLS配置。发布前备份数据库和图片，执行Alembic后再开放API。失败时优先回退应用镜像；涉及不兼容结构时恢复到新建空目标并核验，不自动破坏现有数据。

## 验证证据

实际验证结果单独记录于VERIFICATION.md。已完成生产镜像构建和随机命名Compose栈的备份恢复、TLS、PWA浏览器测试。测试使用一次性自签证书，公开域名与正式证书由实际部署环境提供。构建期间使用临时本机代理解决原有失效代理，未修改系统配置。

## 后续迭代

按产品价值逐项加入：自定义间隔规则、周视图、任务模板、成长展示、内容批量导入、偏好卡池；多家庭和公开服务需先增加家庭归属、监护关系、注册恢复与数据管理流程。App通过认证适配器渐进引入，不提前引入微服务。
